# 产品评审优化 · 设计

来源：2026-10-29 产品评审中的 12 条建议，用户批准「都修，都按照推荐来」。涉及数据库迁移，按完整流程执行。

## 决策（评审中留了选择的地方，由 AI 按推荐定）

| # | 问题 | 决定 |
| --- | --- | --- |
| 1 | 没打分也能进入已落地 | 「已落地」也需要评分（`checkTransition`）；已落地的想法不能清除评分。**JSON 导入不收紧**，历史导出里未评分的已落地想法仍能原样导回（PRD F6.1） |
| 2 | 跳级移动让转化率虚高 | **不限制跳级**（不改变拖拽习惯）；概览返回并展示「曾跳过阶段」的想法数，并在漏斗卡片上说明口径 |
| 3 | 收集箱超过 50 条时，筛选小结会说错 | 小结里的剩余数量取服务端的实时数；还有没看过的想法时，提供「继续下一批」（按游标续读，跳过的不会重复出现） |
| 4 | 评分修改不进时间线 | 新增事件类型 `score`，备注里写「7.6（I 7 / C 8 / E 8）」或「清除评分」；10 分钟内连续调整合并成一条，避免拖动滑块时刷屏；带评分的阶段移动也会记录 |
| 5 | 筛选时没法补充信息 | 筛选卡片增加「打开详情」（复用详情抽屉）；描述按 Markdown 渲染；卡片内容实时跟随详情里的修改；在详情里移走的想法自动计入小结 |
| 6 | 中途退出会丢小结 | 已处理过想法时，「退出筛选」先显示本次小结 |
| 7 | 中段停滞 | 阈值：评估中 30 天、验证中 30 天、执行中 60 天，按 `updated_at` 计算（添加备注也算活动，会更新 `updated_at`）；看板顶部提示、卡片显示「停滞」标记；列表新增排序「最久没更新」 |
| 8 | 验证中缺少结构 | 想法新增「验证假设」「成功标准」两个字段（可选）；进入验证中时，如果两项都没填，弹窗里一起填（可留空）；详情页从验证中开始显示这一区块；写结论时对照显示 |
| 9 | 概览看不到成功指标 | 概览顶部显示 4 个指标：超期积压（目标 ≤ 10）、中段停滞、评分覆盖率（验证中 / 执行中 / 已落地）、结论覆盖率（已落地 / 已放弃）；比率向下截断 |
| 10 | 标签越积越多 | 筛选和自动补全隐藏 0 条的标签；设置页增加标签管理：重命名（改成已有的名字即合并）、删除 |
| 11 | 记录后想马上补充 | 记录成功的提示带「打开」按钮 |
| 12 | 登录过期后导出 | 导出改为 fetch 下载，401 时走统一的跳转登录逻辑 |

## 数据库迁移

`prisma/migrations/<时间戳>_review_improvements`：

- `ideas` 新增 `hypothesis text NOT NULL DEFAULT ''`、`success_criteria text NOT NULL DEFAULT ''`（只加列，带默认值，对已有数据安全）。
- `idea_events.type` 的 CHECK 约束增加 `'score'`（先 `DROP CONSTRAINT IF EXISTS idea_events_type_check`，再重新添加）。

## 接口变化（均向后兼容）

- `Idea` 增加 `hypothesis`、`successCriteria`；`PATCH /api/ideas/:id` 支持这两个字段；`POST /api/ideas/:id/stage` 支持可选的 `plan`。
- `IdeaEvent.type` 增加 `score`。
- `GET /api/stats` 增加 `stalled`（按阶段统计）。
- `GET /api/insights` 增加 `skipped`、`metrics`。
- `GET /api/ideas` 的 `sort` 增加 `updated_asc`。
- 新增 `PATCH /api/tags/:name`（body `{ name }`）、`DELETE /api/tags/:name`。
- 导出文件仍是 `version: 1`，新字段在导入时可省略（默认空字符串），旧文件可以继续导入。
